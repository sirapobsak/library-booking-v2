# เซนเซอร์ตรวจจับเสียง ESP32

บอร์ด ESP32 ติดที่โต๊ะ 1 ตัวต่อ 1 ที่นั่ง ถ้าเสียงดังต่อเนื่องประมาณ 1 วินาที บอร์ดจะแจ้งไปที่ Supabase
แล้วระบบจะ**หักคะแนนสะสมของทุกคนที่จองที่นั่งนั้นอยู่ในตอนนั้น** (คนจอง + เพื่อนที่เข้าร่วมด้วย QR)
ถ้าไม่มีใครจองอยู่ ระบบจะไม่หักแต้มใคร

```
ไมค์ ─▶ ESP32 ─(WiFi/HTTPS)─▶ Supabase: report_noise ─▶ หาการจองของที่นั่งนี้ตอนนี้ ─▶ หักแต้ม + บันทึกประวัติ
```

## ของที่ต้องใช้

- ESP32 (เช่น ESP32 DevKit V1)
- โมดูลไมโครโฟนที่มีขา Analog ออก เช่น **MAX4466**, **MAX9814** หรือ **KY-038** (ใช้ขา AO)

| โมดูลไมค์ | ESP32 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| AOUT / OUT / AO | GPIO34 |

> ต้องใช้ขา ADC1 (GPIO32–39) เท่านั้น เพราะ ADC2 ใช้ไม่ได้ตอนเปิด WiFi

## ขั้นตอน

1. **สร้างอุปกรณ์ในเว็บ:** ล็อกอินด้วยบัญชีผู้ดูแล → **ผู้ดูแล** → แท็บ **อุปกรณ์เซนเซอร์** → เลือกที่นั่ง → **เพิ่มอุปกรณ์**
2. หน้าเว็บจะแสดงโค้ด 4 บรรทัด (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DEVICE_ID`, `DEVICE_KEY`) → กด **คัดลอกโค้ด**
   **คีย์แสดงแค่ครั้งเดียว** ถ้าทำหายให้กด **สร้างคีย์ใหม่**
3. เปิด `noise_sensor/noise_sensor.ino` ใน Arduino IDE → วาง 4 บรรทัดนั้นแทนส่วน "ตั้งค่าเซิร์ฟเวอร์" → ใส่ชื่อ/รหัส WiFi
4. เลือกบอร์ด **ESP32 Dev Module** (ต้องติดตั้ง board package "esp32 by Espressif" ก่อน) → Upload
5. เปิด **Serial Monitor** (115200) ควรเห็น `[heartbeat] HTTP 200 {"ok": true, ...}` และในหน้าผู้ดูแล อุปกรณ์จะขึ้นเป็น **ออนไลน์**

## ปรับความไวของเซนเซอร์

เปิด **Tools → Serial Plotter** จะเห็นกราฟ `level` (ความดัง) กับ `threshold` (เส้นเกณฑ์)

- ลองให้ห้องเงียบ ดูว่า level ปกติอยู่ประมาณเท่าไร
- ลองคุยเสียงดัง ดูว่า level ขึ้นไปถึงเท่าไร
- ตั้ง `LOUD_THRESHOLD` ให้อยู่ระหว่างสองค่านั้น แล้วอัปโหลดใหม่

ค่าอื่นที่ปรับได้ในโค้ด:

| ค่า | ความหมาย |
|---|---|
| `LOUD_WINDOWS_TO_TRIGGER` | ต้องดังนานแค่ไหนถึงจะนับ (20 × 50 ms ≈ 1 วินาที) |
| `LOCAL_COOLDOWN_MS` | ส่งแล้วพักฝั่งบอร์ดกี่มิลลิวินาที |

ส่วน **จำนวนแต้มที่หัก** และ **ช่วงพักฝั่งเซิร์ฟเวอร์** ตั้งได้ในหน้าผู้ดูแล → แท็บ **ตั้งค่า** (ไม่ต้องแก้โค้ดบอร์ด)

## ทดสอบโดยไม่ต้องมีบอร์ด

- ในหน้าผู้ดูแล → อุปกรณ์เซนเซอร์ → กด **จำลองเสียงดัง** (ทำงานเหมือนบอร์ดส่งมาจริง)
- หรือยิงคำสั่งเองจากคอม (แทนค่าในวงเล็บเหลี่ยม):

```bash
curl -X POST "[SUPABASE_URL]/rest/v1/rpc/report_noise" -H "apikey: [SUPABASE_ANON_KEY]" -H "Content-Type: application/json" -d "{\"p_device\":\"[DEVICE_ID]\",\"p_key\":\"[DEVICE_KEY]\",\"p_level\":2000}"
```

## ความหมายของคำตอบ

| status | ความหมาย |
|---|---|
| `DEDUCTED` | หักแต้มแล้ว (`users` = จำนวนคน, `penalty` = แต้มที่หักต่อคน) |
| `NO_BOOKING` | ตอนนี้ไม่มีใครจองที่นั่งนี้ — ไม่หักแต้ม |
| `COOLDOWN` | เพิ่งหักไป ยังอยู่ในช่วงพัก (`retry_in` = อีกกี่วินาที) |
| `SENSOR_OFF` | ผู้ดูแลปิดการหักแต้มจากเซนเซอร์ไว้ |
| `DEVICE_DISABLED` | ผู้ดูแลปิดใช้งานอุปกรณ์ตัวนี้ |
| error `BAD_DEVICE` | `DEVICE_ID` หรือ `DEVICE_KEY` ผิด |

## แก้ปัญหา

- **`HTTP -1`** — ต่อ WiFi ไม่ได้ เช็คชื่อ/รหัส และ ESP32 รองรับแค่ WiFi 2.4 GHz
- **`BAD_DEVICE`** — คีย์ผิดหรืออุปกรณ์ถูกลบ ให้กด **สร้างคีย์ใหม่** แล้วอัปโหลดโค้ดใหม่
- **ขึ้น DEDUCTED ไม่ได้สักที** — เช็คว่ามีคนจองที่นั่งเดียวกับที่ผูกอุปกรณ์ไว้ **และอยู่ในช่วงเวลาที่จองตอนนี้**
- **level ค้างที่ 0 หรือ 4095** — สายขา AO หลวม หรือเสียบผิดขา

## เรื่องความปลอดภัย

- `SUPABASE_ANON_KEY` เป็นคีย์สาธารณะ (อยู่ในหน้าเว็บอยู่แล้ว) — ยืนยันตัวอุปกรณ์ด้วย `DEVICE_KEY` แทน
- ฐานข้อมูลเก็บ `DEVICE_KEY` แบบ hash เท่านั้น เลยดูย้อนหลังไม่ได้ ต้องสร้างคีย์ใหม่อย่างเดียว
- `client.setInsecure()` ข้ามการตรวจใบรับรอง HTTPS เพื่อให้ทดลองง่าย ถ้าจะใช้งานจริงควรใส่ root CA ของ Supabase
